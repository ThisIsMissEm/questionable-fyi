# Replace Hardcoded NSID Literals with `@lexicons` Imports

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every hardcoded `fyi.questionable.richtext.*` NSID string literal in `inertia/` with the corresponding generated constant imported via `@lexicons/*`, so that future lexicon renames (the next `bskyPost`-style change) are caught at compile time instead of failing silently at runtime.

**Architecture:** The generated lexicon defs export both a module-level `$nsid` constant (the lexicon's namespace ID, e.g., `'fyi.questionable.richtext.text'`) and per-typed-object `.$type` properties (the discriminator string, e.g., `'fyi.questionable.richtext.facet#mention'`), both preserved as *literal* types via `@atproto/lex-schema`'s `TypedObjectSchema<const TType extends NsidString>` template. Both narrow correctly in TypeScript switches. We import the entire richtext namespace once via the codegen-provided barrel at `@lexicons/fyi/questionable/richtext` and access constants through it.

**Which constant to use where:** For lexicons that are just a single `main` def (`text`, `header`, `blockquote`, `code`, `list`, `horizontalRule`, `content`) use `richtext.<name>.$nsid` — that's the lexicon's identifier, and for mains it equals the discriminator string. For facet **sub-defs** (`mention`, `link`, `bold`, `byteSlice`, etc.) use `richtext.facet.<sub>.$type` — `$nsid` only exists at the facet module level (`richtext.facet.$nsid === 'fyi.questionable.richtext.facet'`, no hash), and we need the full `nsid#hash` discriminator that only `.$type` carries. Rule of thumb: `$nsid` for lexicon types, `$type` for sub-defs of a lexicon type that has many of them.

**Tech Stack:** TypeScript, `@atproto/lex` / `@atproto/lex-schema`, Vite path alias `@lexicons/* → app/app/lexicons/*`, Vitest.

## Import shape (used throughout the plan)

A single namespace import per file:

```ts
import * as richtext from '@lexicons/fyi/questionable/richtext'
```

That barrel (`app/app/lexicons/fyi/questionable/richtext.ts`) is generated by `@atproto/lex` and re-exports each lexicon as a sub-namespace (`* as text`, `* as header`, `* as facet`, …). Access pattern:

- Block lexicons (single-`main`): `richtext.text.$nsid`, `richtext.header.$nsid`, `richtext.blockquote.$nsid`, `richtext.code.$nsid`, `richtext.list.$nsid`, `richtext.horizontalRule.$nsid`.
- Top-level container: `richtext.content.$nsid`.
- Facet sub-def discriminators: `richtext.facet.bold.$type`, `richtext.facet.italic.$type`, `richtext.facet.mention.$type`, `richtext.facet.link.$type`, `richtext.facet.abbr.$type`, etc.
- `byteSlice`: `richtext.facet.byteSlice.$type`.

**No shadow concerns** with this shape: although `lexicon_to_tiptap.ts:67` and `content.tsx:37` both use `facet` as a loop variable, the generated barrel's namespace is `richtext`, so `richtext.facet.bold.$type` references the lexicon facet without colliding with any local `facet` variable.

**Generated-barrel caveat:** project preference is to avoid hand-rolled barrel files in `inertia/`. The `@lexicons/fyi/questionable/richtext` barrel is generated by codegen and is the canonical entry to the richtext lexicons — consuming it is not the same pattern as adding our own re-export shim, so it's fine to use here.

- [ ] **Step 4: Replace `markToFeature` literals and tighten the link cast**

Note the `link` cast: `l.UriString` is the template literal type `` `${string}:${string}` `` (not a brand) and a bare `as string` won't satisfy it, so we cast to `l.UriString` and let lexicon validation enforce the actual format downstream.

  switch (mark.type) {
    case 'bold':
      return { $type: richtext.facet.bold.$type }
    case 'italic':
      return { $type: richtext.facet.italic.$type }
    case 'underline':
      return { $type: richtext.facet.underline.$type }
    case 'strike':
      return { $type: richtext.facet.strikethrough.$type }
    case 'code':
      return { $type: richtext.facet.code.$type }
    case 'highlight':
      return { $type: richtext.facet.highlight.$type }
    case 'subscript':
      return { $type: richtext.facet.subscript.$type }
    case 'superscript':
      return { $type: richtext.facet.superscript.$type }
    case 'abbr': {
      const title = mark.attrs?.title
      if (typeof title !== 'string') return null
      return { $type: richtext.facet.abbr.$type, title }
    }
    case 'link':
      return { $type: richtext.facet.link.$type, uri: mark.attrs?.href as l.UriString }
    default:
      return null
  }
}
